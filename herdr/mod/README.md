# The factory mod for the Herdr desktop app

The mod of the epic "the maintainer runs the factory from a Herdr mod". The approved designs are in [`design/`](design/README.md); this folder holds what is built from them.

## The agent cats

A mod draws an image from a file under the app's configuration folder (`image("mods/<name>/…svg")`), so every cat the panel shows exists as a file. The source of all of them is [`design/cats.json`](design/cats.json) (the figures, the states, the crops and the badges) with the colours of [`design/tokens.json`](design/tokens.json).

```bash
node herdr/mod/build-cats.mjs              # writes herdr/mod/factory/cats/
node herdr/mod/build-cats.mjs --out <dir>  # writes them to <dir>
```

It reads only those two files, uses Node built-ins only and writes `<role>-<state>-<crop>-<theme>.svg`: 6 roles (`planner`, `master`, `worker`, `reviewer`, `verifier`, `scribe`), 5 states (`working`, `needs`, `idle`, `held`, `red`), 2 crops (`full`, `head`) and 2 themes (`dark`, `light`), 120 files, each with `viewBox="0 0 100 100"`. The same input gives the same bytes. `herdr/mod/factory/cats/` is in `.gitignore`: the files are generated, never committed.

Each file draws, in the order of the source: the silhouette (the role's body, stroked with the state's outline), the collar, the bell, the object's fill, the ink, then the eyes and the marks of the state. The `head` crop adds the role's round badge. The colours of the outline, the bell and the pause mark are the theme's tokens, so a file exists once per theme; the body, the ink and the collar are the role's own (the reviewer's ink and collar are `#e8f0ff`, the others' `#0b0c10`).

The glow of "needs you" is not in the files: the panel draws it.

`catFile(role, state, size, theme)` in [`factory/lib/cat.js`](factory/lib/cat.js) gives the name of the file to draw: the `head` crop under 32 px, the `full` crop from 32 px, and `undefined` for a name that has no role.

## The model

Every screen of the mod shows the same facts, so they are read once, by plain functions in [`factory/lib/`](factory/lib/) that import only each other and that vitest runs (`test/herdr-mod-model.test.ts`, with the recordings in `test/fixtures/herdr-mod/`). No function reads the clock, a file or the network: the time, the texts and the fetched JSON are arguments, and the calls that fetch them are the mod's own.

| Module       | Reads                                                                                                                                         | From                                                                                                                                                               |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `slots.js`   | the heavy slots, the leases, the queue, the orphans, `paused` and the maintainer's hold                                                       | the text of `herdr/factory-slot.sh status` (`status.txt`, `status-paused.txt`); the script prints no queue line today, and a `queue` line is read when it does     |
| `machine.js` | the 1-minute load, the memory in use (`MemTotal` minus `MemAvailable`), a CPU temperature; saturated when the load is above the core count    | the texts of `/proc/loadavg`, `/proc/meminfo` and each `hwmon` `name` with its `temp1_input`, and the core count (`herdr/mod/findings.md`, question 3)             |
| `gates.js`   | an issue's rounds, the six marks of its track (passed, running, needs you, held, red, not reached, omitted by lane), its lane and calibration | the issue's comments as `gh api repos/<repo>/issues/<n>/comments` returns them: only the maintainer's login counts, as in `factory-tools metrics` (`--maintainer`) |
| `issues.js`  | a milestone's issues as rows: the track, the lane, the age of the wait and what blocks a blocked issue                                        | the milestone's issues as REST returns them and each one's comments; a `## Depends on` item that is an open issue of the milestone blocks it                       |
| `agents.js`  | each agent's name, role, status and space                                                                                                     | the rows of Herdr's `terminals()`, never `agents()` (findings, question 4)                                                                                         |
| `state.js`   | all of it, with an age per source and a `stale` mark on a source whose last read failed (it keeps its last value)                             | what the other modules read, as one `fetched` object                                                                                                               |

The gate comments are those of `herdr/master.md`: `**Gate 1 …**` with a `lane: <lane>` line (and `(calibration: full)`), `**Gate 2, round K …**`, `**Gate 3, round K (reviewer-N)** · K Blocking …` and `**Gate 4, round K …** · M mismatches`. A comment with a Blocking above 0, a mismatch above 0 or `not ready` marks its gate red until a later round of that gate passes; `express` omits G3 and G4. G5 needs the maintainer once the gates before it passed, G5 is passed from the `Progress updated … pull request #N opened` comment and a closed issue has every gate passed. The `held` mark is to be read from the `held |` comment of "The lines" below; the model does not read it yet, so no issue is held.

A role comes from a terminal's `name` (`worker-<N>`, `reviewer-<N>`, `reviewer-<N>-r<K>`, `verifier-<N>`, `verifier-<N>-r<K>`, `scribe`) or, with no name, from `--agent master` or `--agent planner` in `foreground.argv`. Its status is the terminal's `status`, and `blocked` means it needs the maintainer. Its space is that of its root terminal (the one with no `parent`), from that root's `herdr.space` label. The state carries no context size and no model: no field of `agents()` or `terminals()` gives a context size, and the model is only an argument of a command. The issue detail reads it where it is, with `modelOf` of `agents.js`: the argument after `--model` in a terminal's `foreground.argv`, `--` for a terminal that was started with none (the master's).

## The panel

[`factory/`](factory/) is the mod: a panel docked on the right of the window (`mod.json`: `place: right`, 380 px) that shows the state of the factory and, in "Needs you", sends the maintainer's sign-offs and answers to the masters. No command it runs for a read writes. It sends the lines of "Needs you" below, to the master of an issue's space and after the maintainer's click and a 10 s undo, and `retry #N` once for a retry the maintainer armed; the buttons of "The buttons" below act on the machine; it reads no token and stores none (`gh` finds its own login). `main.js` puts the reads of [`adapters.js`](factory/adapters.js) through the model above and the sections of [`factory/lib/panel.js`](factory/lib/panel.js) into one description, which one file of [`factory/views/`](factory/views/) per section draws: `header.js`, `strip.js`, `banners.js`, `machine.js`, `slots.js`, `leases.js`, `needs.js`, `milestones.js` (with `legend.js`), `stacks.js` and `orphans.js`, `detail.js` for the overlay of an issue and `board.js` for the Board tab.

### The issue detail

The id of an issue row in Milestones (and `herdr-app do factory.detail:<number>`) opens an overlay of the same mod, a dialog 760 px wide, with `detail` in its props (`main.js` draws [`views/detail.js`](factory/views/detail.js) when it has it; what it shows is computed by [`factory/lib/detail.js`](factory/lib/detail.js) and run by `test/herdr-mod-detail.test.ts`). It reads, and sends one thing: the answer of "Decision for you" (below) to the space's master, after the 10 s countdown; closing the overlay cancels the countdown, and nothing is sent. Nothing else:

- The header: the space's badge, the lane tag, the repository and number, the branch, the stack (`stack up: <name>` when `docker compose ls` lists a stack that ends with the issue's number, else `no stack up`: the design's "no stack needed" would need a source for what the issue needs, and none is given), the lines added and removed, and the title. The branch and the lines are read from the worktree named in the issue's `### Progress` (`git rev-parse --abbrev-ref HEAD` and `git diff --numstat` against the merge base with `origin/main`, nothing that writes; a file that is not tracked yet is not counted).
- "Gates by round": one row per round, six cells G1 to G6. A cell holds the first line of the gate comment of that round, after `Gate N, round K (agent)`; a gate the lane omits is dashed in every row. A gate with no comment yet shows what its mark says (`running`, `needs you`, `waits`), and in the earlier rounds `--`.
- "Agents on this issue": the issue's agents (`worker-<N>`, `reviewer-<N>`, `verifier-<N>` and their reread names) and the space's master, each with its cat, model, state and tokens: input plus output summed from the `tokens |` lines of the issue's comments (`herdr/master.md`, "The tokens record"; the maintainer's login only, the issue's number only, one total for each role). An agent that has ended has no terminal any more: its row is made from its tokens line, state `done`. The design's Context column is left out, and so is the line under it that depends on it: no field of `terminals()` gives a context size (`findings.md`, question 4).
- "Packet": the worktree, the draft, the decisions file (`<packet>/r<K>/decisions.md`, K the latest round) and the commit message (`<packet>/commit-message.txt`), from the code spans after `worktree`, `packet directory`, `draft` and `branch` in the `### Progress` section of the issue (`herdr/master.md`, "The review packet"). A path opens its file in a pane running `less`; an agent's name opens a pane running `watch -n 2 hc read <terminal> --lines 40`, so the keys go to `watch` and never to the worker. Each closes the overlay.

- "Decision for you", when the master has an open `**Decision needed**` comment on the issue: the question, one option per list item (A, B, …), a note and "Send to <space> · master". It sends `answer #N: <option>[ — <note>]` through the 10 s countdown, as "Needs you" does. The comment is open until a later comment of the maintainer's login starts with `Maintainer's decision, relayed by the master` (the form the master posts the answer in).

The design's "Log a correction" link (issue #306) is not in it.

### Needs you

[`factory/views/needs.js`](factory/views/needs.js) is the first section of the panel, after the banners, and has no fold: it is there while something waits and gone when nothing does. What it shows is computed by [`factory/lib/needs.js`](factory/lib/needs.js) and [`factory/lib/time.js`](factory/lib/time.js) and run by `test/herdr-mod-needs.test.ts`. One card for each wait, oldest first, each with its age and the cat of the agent that waits:

- **A master that is blocked**: "Go to master" focuses its pane (`pane.focus`). `terminals()` gives no time for a status, so its age is counted from when the panel first saw it blocked, and it restarts with the panel. `blocked` is read as the model reads it ("needs the maintainer"), with the caveat of "What each section reads": `hc get` reported `blocked` for a worker that was only running a long shell command, so the card can be a false alarm, and the text says "Waiting for your reply in its pane."
- **A sign-off**: an issue whose G5 needs you and whose lane is not `express`. The review and verification lines are what the last Gate 3 and Gate 4 comments say after `Gate N, round K (agent)`, the lane is the `lane:` line of the Gate 1 comment with the lines under it as the reason, and the commit's subject is the first line of `<packet>/commit-message.txt`. "Open diff" opens `git diff` against the merge base with `origin/main` of the worktree named in the issue's `### Progress`, in a pane running `less`; "Reports" opens `gh issue view <n> --comments` in one. The time form and the sign-off stay locked, in every lane, until "Open diff" was clicked for that issue in this session (kept in memory: a reload of the mod locks it again).
- **A decision**: an issue with an open `**Decision needed**` comment. "Answer through the master" opens the issue detail, whose "Decision for you" block takes the option and the note.
- **The green `express` issues**: one card for each space, so a click sends exactly one message, to that space's master. "Read the N diffs" opens the diff of each one not read; "Sign off K express" sends `approved, sign off #N #M` for the K whose diff was read and that are `express`, and no time line.

The time form of a sign-off is `TimeForm`: what was read first (Diff or Reports), the minutes (counted since the diff was opened, kept up to date until edited), the hands-on check (None, Stack, Test, and only in `full`), a remark (its parentheses and line breaks are dropped) and the lines it will send, `approved, sign off #N` and `time: <minutes>m diff|report[, <minutes>m stack|test][ (<remark>)]`. The "Start timer" of the design is not in it.

A click on the sign-off, or on "Send to <space> · master", starts a 10 s countdown with an "Undo"; undone, nothing is sent, and at 10 s exactly one `hc send <master's terminal> <text>` is made (`lib/needs.js`, `createOutbox`; the two lines of a sign-off are one message). The master is the terminal with `--agent master` whose root has that space's label; with none, the button is off. `hc send` refuses a master that reported `blocked` (exit 9) and the panel does not force it: the line is not sent and the panel says why. With `fixture` in the props the countdown runs and nothing is sent. No call of this section writes to a worker's pane or to GitHub.

A desktop notification (`notify`, level `warning`, its action the command `factory.reveal:needs` of the docked panel, which scrolls it to "Needs you"; `mod.open` would open a new copy of the mod with no props) is posted when a card appears that the last look did not have; the first look after the panel starts posts none. In a fixture none is posted.

### The Board

"Open board" in the heading of Milestones (and `herdr-app do tab.new --name Board --mod factory --props '{"board":true, …}'`, with the block's other props) opens this mod as a tab of its own with `board` in its props (`main.js` draws [`views/board.js`](factory/views/board.js) when it has it; what it shows is computed by [`factory/lib/board.js`](factory/lib/board.js) and run by `test/herdr-mod-board.test.ts`). It reads and sends nothing: a card opens the issue detail and does nothing else, and there is no dragging.

- The summary: load (the 1-minute load over the core count, magenta above 75 % of it and red above it), heavy slots, workers, queue, orphans and the factory's share.
- The filters: one button per space, `<SPACE> · <closed>/<all>` (the pull requests merged, as in Milestones), and one per lane (`EXPRESS`, `NORMAL`, `FULL`). They combine and the counts of the columns follow them; the summary does not. The design's "ctx 201k" is left out: no field of `terminals()` gives a context size (`findings.md`, question 4).
- Seven columns: Ready, G2 · Worker, G3 · Review, G4 · Verify, G5 · Needs you (the maintainer's, dashed magenta), G6 · CI and Merged today. An issue is in one column, the one its last gate comment puts it in: no gate comment is Ready; a gate sent back, and a red gate 2, is G2; a red gate 3 or 4 stays in its own column marked red; a gate that passed sends it to the next gate its lane does not omit and that has not passed (G3 and G4 run together, so an issue is in G3 until its review passed); `Progress updated … pull request #N opened` moves it to G6. A closed issue is in Merged today when it was closed today (UTC). The design draws an issue twice while G3 and G4 run together; the Board does not (it is in exactly one column).
- Ready is the Status Ready. The Status of the project is a GraphQL read (or a REST read that needs the project's number), and the panel runs `gh api` GET calls only: an open issue with no gate comment is in Ready when it has the label `ready`, which `issue-ready` sets with the Status, and it is Todo, and not on the Board, without it.
- A card: the space's badge, `#<issue>`, the lane tag, the round, a sentence (the title; `Blocked by #N` for a blocked one; `Waits for your sign-off` in G5; the first line of a red gate's comment), the cat and name of the issue's agent for that column (the worker in G2, the reviewer in G3, the verifier in G4, the space's master in G5 and G6; any other agent of the issue, none in Ready) and how long since the last gate comment (`waiting 4 h` for a card that needs you, `held 6 min` for a held one). A card that needs you is magenta, a held one has the acid stripe (the model reads no held issue yet, see "The model"), a red one is red.
- The factory's share is the issues of the milestones whose `front` is `Foundations` in `.github/project-fields.json` (the `frontByRepository` of a repository first) over the issues of every milestone of the same `releaseLine`, in the repositories of the spaces; a milestone's issues are its `open_issues` and `closed_issues` of `gh api repos/<repo>/milestones?state=all`. The line is that of the first space's milestone found in the file; with none, the share is `—`.

The Board's tab reads on the same timers as the panel (5 s and 60 s); the milestones and the file are read with the 60 s read of GitHub. The comments of an issue closed today are read too, for the lane of its card. At the window's width the Board scrolls sideways below 1330 px, as the design does.

### Install

```bash
herdr/mod/install.sh --maintainer <your GitHub login> --spaces <spaces.json>
```

It builds the cats and copies the mod to `${HERDR_APP_DIR:-$HOME/.config/herdr-app}/mods/factory/` and the layout to `layouts/factory.json` (Herdr's `main` with the panel on the right; `layout.switch {name: "factory"}`, or `ctrl-shift-l`, shows it). It never overwrites a file it did not write: it records the hash of each file it writes in `factory-mod-install.json` of that folder, and when a file it would write exists with another hash (one it did not write, or one it wrote and you then edited) it writes nothing, names the file and exits 1. Run again, it replaces what it wrote. An install made before the `dockerHost` prop existed runs `docker` with no `-H` until `install.sh` is run again. `--fixture <folder>` (repeatable) makes it read recordings, as below. The mod follows the Herdr app's theme and has no theme option: change the light or dark mode and the colours with the app's own theme menu or `app.theme`. Herdr loads the `fonts/` folder at start and at the next look change, not when the mod reloads: a first install shows the interface font until then.

### Configure

The block's props in `layouts/factory.json` (`install.sh` writes them):

| Prop         | Meaning                                                                                                                                                                                                                                 |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `checkout`   | this repository's checkout, where `herdr/factory-slot.sh` is (`install.sh` sets it to the one it ran from)                                                                                                                              |
| `maintainer` | the login whose comments are the master's gate comments (`--maintainer`, else `$FACTORY_MAINTAINER`)                                                                                                                                    |
| `spaces`     | one `{ "name", "repo", "milestone", "epic" }` per space: the Herdr space's name, its repository, the milestone's number and the epic's number (left out of the rows)                                                                    |
| `dockerHost` | the socket of the host's container engine, `unix://${XDG_RUNTIME_DIR:-/run/user/$(id -u)}/podman/podman.sock` (`install.sh` writes it, ADR-0002); every `docker` call is `docker -H <dockerHost> …`, and with none it runs with no `-H` |
| `fixture`    | a folder, or a list of folders (the first that has a file gives it): the panel reads their recordings and runs nothing                                                                                                                  |

The mod follows the app's theme: the light or dark mode (`settings().dark`) and the neutral colours (`bg` from `canvas`, `surface`, `surface2` from `raised`, `line` from `border`, `fg` from `foreground`, `muted`), read from `theme()` at each render, so a change shows within 5 s. The colours of meaning (running, needs you, red, held) stay the design's, for the app's mode, and a colour the app's theme lacks keeps the design's. A `theme` that an earlier install left in `localStorage` or in the layout is ignored.

A section folds with a click on its heading; the fold is kept in the mod's `localStorage`. Whether it survives a restart of the app was not run (`findings.md`, question 12). The commands `factory.top` and `factory.reveal:<section>` (`herdr-app do factory.reveal:milestones`; `needs`, and `card-<n>` for the nth card of Needs you) only scroll the panel, and `factory.detail:<number>` opens the overlay of an issue.

### The buttons

Four things the maintainer does when the machine saturates, each a click that [`factory/lib/actions.js`](factory/lib/actions.js) runs through Herdr's `exec` (`test/herdr-mod-actions.test.ts` runs them through a stub, never the live machine). With `fixture` in the props nothing runs at all: `createActions` and `createRetries` of `lib/actions.js` take `disabled`, which `main.js` sets from `fixture`, so no slot script command, no `docker`, no `kill` and no `retry` send is made whatever is clicked, and a click says "Fixture: nothing was run." (`test/fixtures/herdr-mod/actions/` holds the paused state, a held check, an unowned stack and an orphan for the shots).

- **"Pause new workers" / "Resume workers"** (under the alarms, with the paused line the design shows): `herdr/factory-slot.sh pause` and `resume`. The label follows the `paused` line of `status`, read every 5 s and again after a click.
- **"Reserve a slot" / "Release my slot"**: `herdr/factory-slot.sh hold --agent maintainer` and `release --agent maintainer`. A hold that exits 75 holds nothing and the panel says "no free slot". The label follows the `held` slot of `status`.
- **A held check in "Needs you"**: a card for the last `held | <date> | #N | <gate> | <reason>` line of an issue's comments, until a later comment of the same gate reports the rerun. It shows the reason and "Retry when load < 24" (three quarters of the core count, so 24 on the design's 32 threads and 6 on 8 cores), which arms it: when the 1-minute load falls under that number the mod sends `retry #N` to the issue's master (the line of "The lines" below), once, and the retry is no longer armed. "Armed · cancel" disarms it. An armed retry lives in the mod's memory: closing the panel drops it.
- **Stacks up and Orphans**: a stack with no live agent and no lease shows its age (the oldest container, `docker -H <dockerHost> ps -a --filter label=com.docker.compose.project=<project>`) and "Bring down <project>…", which after a confirmation that names the project runs `docker -H <dockerHost> compose -p <project> down -v` (every `docker` call goes through `dockerArgs`, ADR-0002). An orphan shows "Show process" (its command, working directory, cores and age, from `ps -o etimes=,pcpu=`) and "Terminate…", which after a confirmation that names the process ends its process group with `kill -TERM`. Both are offered only for what no live agent and no lease owns, and are checked again when the confirmation is answered.

### What each section reads

| Section       | Reads                                                                                                                                                                                                                                                                            | Every     |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------- |
| Header, strip | the age of the freshest read; the counts of the other sections (needs: the issues that wait for you and the agents asking, with no issue)                                                                                                                                        | 5 s       |
| Machine       | `/proc/loadavg`, `/proc/meminfo`, `/sys/class/hwmon/*` and `nproc`; the load of the last 15 minutes is the panel's own record of what it read                                                                                                                                    | 5 s       |
| Heavy slots   | `herdr/factory-slot.sh status`                                                                                                                                                                                                                                                   | 5 s       |
| Worker leases | the same text; the letter is the space of the agent that holds it                                                                                                                                                                                                                | 5 s       |
| Needs you     | the same reads as Milestones, the agents from `terminals()`, `<packet>/commit-message.txt` of each open issue whose `### Progress` names a packet; the maintainer's clicks (the diffs opened, the forms)                                                                         | 5 s, 60 s |
| Milestones    | `gh api repos/<repo>/issues?milestone=<n>&state=all` and, for each open issue (and each one closed today), its comments; the agents of each issue from `terminals()`. `PRs a/b` is the closed issues over all of them (the factory closes an issue with its merged pull request) | 60 s      |
| Stacks up     | `docker -H <dockerHost> compose ls --format json` (ADR-0002); a stack belongs to the agent whose issue number ends its name (`wt-792`: `worker-792`), or to the lease of that issue; once for each stack nobody owns, `docker -H <dockerHost> ps -a` for its age                 | 5 s       |
| Orphans       | the `orphan` lines of `factory-slot.sh status`; `ps -o etimes=,pcpu= -p <pid>` when "Show process" is clicked                                                                                                                                                                    | 5 s       |

A failed `gh` makes GitHub stale: the banner gives its age, Milestones keeps its last rows dimmed, and the other sections go on. The panel shows no context size (no field of `terminals()` gives one, `findings.md`, question 4), no memory per stack, and the age of a stack nobody owns is read from its containers (`docker compose ls` gives none). A `blocked` terminal is shown as an agent that may need you, as the model reads it ("needs the maintainer"), with a caveat: `hc get` reported `blocked` for a worker that was only running a long shell command, so a needs-you cat, mark or count can be a false alarm; the note says "is blocked: it may need you". The rows of Milestones are built at each redraw from the agents of the last 5 s read and the last 60 s read of GitHub, so an agent that starts, stops or blocks shows within 5 s. The design's keys are not in the panel yet.

### The lines

What the panel's buttons send (the sign-off and the answer, #304, and the retry, #305; #306 will send more) and what the master posts for the panel to show; the rules are [`herdr/master.md`](../master.md), "Lines from the mod", with `G5.2`, `G5.5`, `M.8` and `C.1` of [`docs/factory.md`](../../docs/factory.md). The mod sends each line bare (`hc send`, no `HC_TERMINAL_ID`), only to the master of the issue's space. The lines of a click (the sign-off, the answer) wait the 10 s undo (ADR-0004); `retry #N` does not: the click only arms it, and the mod sends it once, with no undo, when the load falls under three quarters of the cores ("Armed · cancel" before that disarms it).

Each line the mod sends, and what the master does with it:

- `approved, sign off #N`, followed or not by a line `time: <minutes>m diff|report[, <minutes>m stack|test][ (<remark>)]`: the master signs off (`G5.2`), then posts the `time:` line as the pull request's review comment (`G5.5`).
- `answer #N: <option>[ — <note>]`: it records the answer in `decisions.md` and on the issue, then passes it to the worker.
- `retry #N` (sent by the mod when an armed retry's load is reached, not at a click): it reruns the held check once through `herdr/factory-slot.sh run`; a second failure is red.
- `log #N | <what> | <category>`: it posts `factory-log | <date> | #N | <what> | <category> | -` on the issue.
- `time #N: <the time line>`: it posts the time line on the open pull request that has none.

The master posts on the issue, for the panel to read:

- `**Decision needed** · #N`, the question and one list item per option (`- A: …`), when a worker waits for the maintainer ("Decision for you" of `IssueDetail`).
- `held | <date> | #N | <gate> | <reason>` when a check failed only on timeouts while the load was above the core count (the held check of `PanelSaturated`).

### Fonts

`factory/fonts/` holds Chakra Petch (Medium, SemiBold, Bold) and JetBrains Mono (Regular, Medium, Bold) with the OFL text of each; the views name them by family and pick the weight with `font_medium()`, `font_semibold()` and `font_bold()`. ### Reproducing a screen

With `fixture` set, the panel reads `test/fixtures/herdr-mod/` (`normal/`, `saturated/` and `stale/` hold what differs; `board/` holds the issues, comments, agents, milestones and `project-fields.json` of the Board, `test/herdr-mod-board.test.ts`): `now.txt` is its clock, and `github-error.txt` makes every GitHub read after the first fail. `test/herdr-mod-panel.test.ts` runs the same files through the same functions. `needs/` (two spaces, `fixture-space` and `fixture-other`, whose masters are `tfix-master` and `tfix-master2`, terminals that exist on no host) draws "Needs you": `diffs.json` says how many minutes before `now.txt` each issue's diff was opened, since nobody clicks in a recording, and `commit-<n>.txt` is the commit message of issue `n`'s packet. With a fixture nothing is ever sent.
